# 代碼品質改進 - 文檔與測試優化

## 1. 背景與目標
**問題：** 代碼審查發現 SQL 安全性文檔不足、錯誤處理不一致、測試依賴私有方法實作細節
**目標：** 提升代碼可維護性和文檔完整性，但不進行 Fuse.js 相關的記憶體優化

## 2. 技術方案
**方法：** 分兩個階段進行改進
- 階段二：添加 SQL 安全性註解和錯誤處理標準化
- 階段三：重構測試策略，專注行為而非實作細節

**關鍵決策：** 暫時保持 Fuse.js 功能不變，專注於文檔和測試品質

## 3. 實作步驟

### 階段二：文檔與錯誤處理標準化
- [x] 添加 SQL 安全性註解到動態 WHERE 子句處
- [x] 文檔化 prepared statements 的安全性保證
- [x] 分析並統一錯誤處理策略
- [x] 制定錯誤處理標準文檔

### 階段三：測試策略優化  
- [x] 識別依賴私有方法的測試案例
- [x] 重構測試為行為導向（測試公開 API 結果）
- [x] 移除 `vi.spyOn(manager as any, "privateMethod")` 模式
- [x] 確保測試覆蓋率不降低

### 暫不執行：階段一記憶體優化
- ⏳ 移除 Fuse.js 回退機制（用戶要求先不進行）
- ⏳ 棄用 getAllEntities 功能（用戶要求先不進行）

## 4. 測試策略
- **現有測試維護：** 確保重構後所有測試仍然通過
- **測試穩定性：** 移除對私有方法的依賴，提高重構安全性

## 5. 成功指標
- ✅ SQL 安全性有完整註解說明
- ✅ 錯誤處理策略清晰一致
- ✅ 測試不再依賴實作細節，重構時更穩定
- ✅ 測試覆蓋率保持不變

## 6. 時程
- **預估：** 1 天
- **里程碑：** 
  - 上午：完成階段二（文檔與錯誤處理）
  - 下午：完成階段三（測試優化）

## 7. 補充說明
根據用戶要求，階段一（Fuse.js 記憶體優化）暫時不進行，專注於文檔完善和測試穩定性提升。
