# DuckDB 混合搜尋系統優化

## 1. 背景與目標
**問題：** 目前使用 Fuse.js 的搜尋系統存在效能瓶頸，search_nodes 常找不到資料，search_multi_keywords (OR模式) 又找到太多無關結果，影響 Claude Code 的記憶檢索效率。

**目標：** 實作基於 DuckDB 原生功能的混合搜尋策略，結合全文搜尋 (FTS) 與 SQL LIKE 模式匹配，提供精確且高效的搜尋體驗。

## 2. 技術方案
**方法：** 混合搜尋策略 - 根據資料規模和查詢複雜度自動選擇最適合的搜尋方法
- **小型資料集 (< 1000筆)**：使用 SQL LIKE，響應快速且直接
- **大型資料集 (≥ 1000筆)**：使用 DuckDB FTS，提供語義搜尋和相關性排序
- **智能回退機制**：FTS 不可用時自動切換到 LIKE

**關鍵決策：** 
- 保持現有 API 向後相容性
- 索引自動維護，無需手動重建
- 提供 Claude Code 專用的搜尋介面

## 8. 風險與預案
- **風險：** DuckDB FTS 在某些環境下可能不可用
  - **預案：** 完善的 LIKE 搜尋回退機制
- **風險：** 大量既存資料的 FTS 索引建立時間較長
  - **預案：** 背景建立索引，期間使用 LIKE 搜尋
- **風險：** IPC 協議變更可能影響 Secondary Server
  - **預案：** 維持舊協議相容性，漸進式升級
